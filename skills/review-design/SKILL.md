# 人工审核开发设计

把需求、关键设计决定和实现影响组织成审核人可以逐项判断的开发设计稿。

## S - Scope

- 负责开发设计文档的结构、内容组织、证据区分和人工审核入口。
- 支持先展示目录、生成完整设计、更新既有设计；按用户当前请求选择，不把目录讨论扩展成完整实施。
- 不代替需求文档、代码 Review、任务切分或产品审批；不因生成设计而修改业务代码、数据库或外部系统。

## C - Constraints

- 生成或实质更新设计前读取 [设计模板](assets/development-design-template.md)。保持一级目录稳定，二三级章节按风险增减。不适用章节用一句话说明原因，简单改动不硬凑图或大表。
- 用户已有设计时原地更新并保留明确结论；存在冲突先核对最新用户决定与证据，不把旧方案和新方案同时当成当前结论。
- 区分四类内容：现状、已确认需求／决定、设计建议、待确认。仅有 PRD／聊天／历史文档时不宣称源码已实现；仅有源码时不声称满足产品验收。
- 用户要求人工审核表示文档要可审核，不自动新增“等批准才能继续”的流程。按当前授权完成可交付草稿；审核状态只记录真实结论，不代替用户签字。
- 先说明业务效果，再给实现细节。数据库表关联不能直接推导聚合边界，内部处理状态不能混同用户看到的业务状态。
- 架构发生修改时，架构设计章节必须提供 Mermaid 核心模块调用关系图，不能仅用职责表、数据流图或功能时序图替代。图中标明受影响模块及必要的子模块／分层边界、核心调用方与被调用方、调用方向和跨模块接口／契约，并区分新增、修改、复用及待确认部分；配套说明现状到目标的变化。仅展示核心关系，不展开无关类或全量依赖；无架构修改时明确说明，可不画图。
- 绘制上述图时使用可用的 [module-callgraph](../module-callgraph/SKILL.md) skill，遵守其源码核对和绘图样式：现状与目标分图、`模块.子模块` 节点、模块分组、已有蓝色／拟新增绿色、接口实现虚线及拟议调用文字标记。若该 skill 不可用，按同样约定绘图并说明未能调用，不宣称已执行其流程。
- 涉及有状态、多步骤、跨模块或外部副作用的关键流程时，在功能点设计中提供 Mermaid 时序图；包含主要拒绝／失败分支和提交边界。普通字段或文案改动不强制画图。
- 参考目标仓库实际相似结构确定字段和基础属性；通用模板不能预设所有项目都用 `created_at`、`ver`、软删除、独立事件表或特定 API 路径。
- 若目标仓库提供专项工程 Skill，涉及生命周期时用 `lifecycle-actions`，模型语义用 `business-model`，API 契约用 `api-application`，实际持久化设计用 `data-persistence`；仅加载实际需要的边界。本文档 Skill 不替代它们或要求环境必须安装这些 Skill。

## P - Process

1. 确定当前要求是目录预览、完整设计还是增量更新；读取已有设计、用户决定及目标仓库约定，选择可持久化的交付位置。
2. 读取模板。先提炼需求改动点、现状和目标差异；为待确认问题标明具体影响，不让非阻塞细节妨碍其他章节完成。
3. 按真实输入组织设计；有代码时核对受影响的完整调用链和成熟参考，有材料缺口时标记待验证，不伪造类、接口、表或配置存在。
4. 先确定架构和功能流程，再同步接口、字段、配置、权限、事件、兼容性及验证；同一个决定只详细写一处，其他章节引用。
5. 为需求改动、功能点及接口／数据变更提供轻量编号，并以需求到设计到验收的表格串联；规模小时可合并在需求改动表中。
6. 在首页提炼本次审核关注点；末尾记录设计建议、待确认问题及真实审核结果。仅用户明确确认或材料有依据时将建议标为已确认。

## V - Verification

- 目录包含背景与目标、需求改动、架构、功能、API、数据库、配置；兼容、验收、发布及待确认项按实际范围填写，不遗漏影响。
- 有架构修改时，核查核心模块调用关系图是否位于架构章节，调用方向、模块边界、跨模块契约和变更标记是否与职责表及功能流程一致；不得将拟增组件或待确认关系画成已实现事实。
- 同一概念在功能、时序图、状态表、API、数据库和测试中的含义一致；同一需求有设计落点和验收方式。
- 状态变化、并发、幂等和部分失败在适用时有明确规则；图里承诺的动作不能与正文中的待确认结论冲突。
- 核查 Markdown 链接、代码块和表格；Mermaid 可渲染时检查渲染，否则明确只检查源码，不声称已渲染验证。
- 删除输出文档中的模板提示和未填空项；未知项填写为具体“待确认：问题／影响／关闭条件”，不适用项写原因。
- 交付时区分文档检查和源码／运行验证，不把设计草稿标为已上线、已验收或已批准。

## O - Output

- 目录预览：展示统一目录及各章审核重点。
- 完整设计／更新：交付可点击的设计文档，概括关键决定、变更位置和真正阻塞实施的待确认项。
- 不主动生成任务、提交、部署或向他人发送审核消息；仅在用户另外授权时执行。
